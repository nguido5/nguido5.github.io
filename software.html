Bayesian 64-State POMDP Estimator (BeliefTracker)

  • Transition Sanitization & Burn-In: Sanitizes incoming 64×64 transition matrices (perturbed by εij ∼ U(−0.1, 0.1) in the game engine) against NaN/Inf and zero-sum rows, caches matrix powers (T, T²), and computes the exact 1,000-step rat head-start distribution (b1000 = b0·T¹⁰⁰⁰) from uniform prior b0(i) = 1/64.
  • Multi-Modal Bayesian Sensor Fusion: Extracts 64-bit board masks (_space, _primed, _carpet, _blocked) to evaluate floor-dependent acoustic likelihoods P(noise | x) and noisy Manhattan distance likelihoods P(d | x) with offset distribution e ∈ {−1, 0, +1, +2} at P(e) = (0.12, 0.70, 0.12, 0.06), clamping negative estimates at d = 0: bt+1(x) ∝ [bt(x)·T^k] · P(noise | cell(x)) · P(d_obs | Manhattan(o, x))
  • Search Feedback & Pre-Warmed JAX Rollouts: Zeros out missed search cells, resets to steady-state b1000 on captures, and pre-warms @jax.jit matrix-vector kernels during __init__ so multi-ply forward belief rollouts (predict_layers) incur zero JIT compilation latency during timed play.

Horizon Planning, Macro Context & Sensing Arbitration (SearchEngine)

  • Iterative-Deepening Negamax & Move Ordering: Explores immutable forecast_move states up to depth 13 using alpha-beta pruning, a 120,000-entry Transposition Table (EXACT, LOWER, UPPER bounds keyed on bitmasks, positions, scores, and turns), 3-slot killer moves, and history heuristics.
  • Belief-Conditioned Evaluation & Macro Horizon: Scores leaves via V = 115·P_Δ + 46·Q_carpet + 17.5·C_conv + 4.4·M_mob + 16·R_Δ + 1.1·C_center, weighting top-6 posterior rat cells by inverse Manhattan distance. MacroContext evaluates 2–4 turn horizons to build high-scoring length 4–7 carpet runs (+6 to +21 pts) while penalizing premature short rolls.
  • Opponent Tempo & Sense-vs-Act Arbitration: OpponentTempoTracker diffs 64-bit masks to infer opponent move types and boost safe PRIME setups during low-impact opponent turns. Decouples SEARCH from tree branching, substituting a rat search only when calibrated expected value EV = 4(0.9p) - 2(1 - 0.9p) beats board gain across phase, lead/deficit, cooldown, and opponent hit-rate gates.

Subprocess Sandboxed Tournament Engine & Automated Benchmark Architecture

Python Multiprocessing • Subprocess Sandboxing • JSON Telemetry • Automated Regression

Isolated Process Execution & Fault-Tolerant Runtime (PlayerProcess)

  • Resource & Timing Enforcement: Executes competing agents inside isolated multiprocessing workers with strict resource caps (1,536 MB RAM, 4 GB VRAM, 30s init timeout, 240s total game clock across 40 turns, 5s queue allowance) and optional privilege dropping / seccomp sandboxing.
  • Closed-Loop Clock Pacing (_compute_deadline): Dynamically allocates per-turn compute budgets (0.08s–7.2s, targeting 82% clock spend with an 18s reserve buffer and 1.0s safety margin) based on spend lag, pace ratio, branching factor, and game phase (opening, midgame, endgame).
  • Telemetry Commentary (commentate): Emits live per-turn diagnostics tracking peak posterior probability, search hit rate, active JAX backend, clock spend, tempo windows, and macro-plan cancellation reasons.

Evolutionary Head-to-Head Benchmark Harness (benchmark.py)

  • Multi-Game Stochastic Evaluation: Because transition matrices T'ij and corner obstacles vary stochastically every match, built automated batch harnesses (benchmark.py, run_local_agents_series.py, verify_agents.py) to run parallel multi-game series across the Apex agent lineage (Apex-Mid, Apex-Macro, ApexEvo, Apex-Vanguard, Apex-Hybrid-1).
  • Granular Score-Source & Failure Attribution: Parses match history JSON artifacts to decompose win/loss/tie rates by exact point source (carpet vs. prime vs. rat-search points, plus lost carpet/search penalties), wall-clock think time per turn, and engine termination codes (points win, timeout, invalid turn, crash, OOM).
  • Edge-Case Unit Verification: Validates zero-probability Shannon entropy guards, out-of-bounds search coercion, and duplicate feedback token suppression prior to tournament deployment.
